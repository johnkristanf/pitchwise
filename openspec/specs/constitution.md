# PitchWise

PitchWise is an AI-driven sales practice application for SDRs, AEs, and founders doing founder-led sales to pressure-test their discovery questioning skills. Structured as a two-tier monorepo: `client/` (React 19, React Router v8 Framework mode, Tailwind CSS v4, Vite 8) and `server/` (FastAPI, SQLAlchemy 2.0 async, PostgreSQL/asyncpg, LiveKit WebRTC, uv).

## Setup & commands

### Server (`server/`)
- Install: `uv sync`
- Add dependency: `uv add <package>`
- Dev server: `uv run uvicorn api.main:app --reload --port 8000`
- Database migrations: `uv run alembic upgrade head`
- Create migration: `uv run alembic revision --autogenerate -m "describe_change"`
- Test (all): `uv run pytest`
- Test (single file): `uv run pytest tests/test_sessions.py`

### Client (`client/`)
- Install: `npm install`
- Dev server: `npm run dev`
- Build: `npm run build`
- Start production server: `npm run start`
- Test (single file): `npm test -- path/to/file.test.tsx`
- Lint / typecheck: `npm run typecheck`

## Testing
- **Server tests**: Live in `server/tests/`, named `test_*.py`. Run using `uv run pytest`.
- **Client tests**: Live in `client/app/**/*.test.tsx` or `client/tests/`.
- **Pre-completion requirement**: `npm run typecheck` (client) and `uv run pytest` (server) must pass with zero errors before considering any task complete.
- **Coverage focus**: Target buyer prompt generation, session state transitions, token auth, and coach rubric scoring calculations.

## Code style & conventions
- **React Router Framework Mode**: Use file routes in `client/app/routes/*.tsx` registered in `client/app/routes.ts`. Never use legacy `<BrowserRouter>`, `<Routes>`, or standalone declarative router components.
- **Route types**: Always import types from `./+types/<filename>` (e.g., `import type { Route } from "./+types/home";`). Type loaders and components with `Route.LoaderArgs` and `Route.ComponentProps`.
- **Async everywhere**: All Python database operations, LiveKit communications, and OpenAI calls must use `async`/`await`. Never use blocking sync I/O.
- **SQLAlchemy 2.0**: Use `select()`, `scalars()`, and `mapped_column()` with `Mapped[T]` type annotations. Never use legacy query API (`session.query()`).
- **Database sessions**: Always inject DB sessions in FastAPI endpoints via `Depends(get_db)`. Do not instantiate `AsyncSessionLocal()` directly inside endpoints.
- **Pydantic v2**: Use `model_config = {"from_attributes": True}` for ORM schemas and `field_validator` (not deprecated `@validator`).

## Architecture notes (only what isn't obvious)
- **Hidden State Isolation**: `buyer_profile_state.hidden_state` (constraints, decision criteria, deal breakers) must **NEVER** be sent to the client during an active call session. It is strictly injected into the server-side buyer LLM prompt and only exposed in the post-call evaluation scorecard.
- **Pedagogical simulation friction**: Buyer personas must not be agreeable sycophants. They must adhere to behavioral sliders (objection frequency, price sensitivity, technical depth, friendliness) and require probing, open-ended questions to reveal pain.
- **Talk-to-Listen ratio**: Coach evaluation enforces a target rep talk time under 35%. Rep monologue turns over 45s must trigger coach warnings.
- **Module boundaries**: `server/api/routes/` handles HTTP transport only; all business logic belongs in `server/services/` (buyer simulation, LLM coach evaluation, LiveKit token vending).

## Gotchas / things to avoid
- **Alembic migrations**: Never modify models in `server/models/` without generating and applying an Alembic migration (`uv run alembic revision --autogenerate`).
- **Do not edit typegen files**: Never manually edit files in `client/app/+types/`—they are generated by `npm run typecheck` (`react-router typegen`).
- **Package manager discipline**: Never use raw `pip` in `server/`; always use `uv`. Never use `yarn` or `pnpm` in `client/`; use `npm`.
- **Tailwind v4 configuration**: Do not create `tailwind.config.js` or `postcss.config.js`. Tailwind v4 config is defined purely via `@import "tailwindcss";` and `@theme` in `client/app/app.css`.

## Security
- **Secrets handling**: Never commit `.env` files. Backend secrets (`SECRET_KEY`, `OPENAI_API_KEY`, `LIVEKIT_API_SECRET`, `DATABASE_URL`) are read via `server/core/config.py`.
- **Client variables**: Never put API secrets in `client/`. Client variables exposed to Vite must be prefixed with `VITE_`.
- **Password storage**: Passwords must always be hashed with Argon2 or Bcrypt via `server/core/security.py`. Never log or return password hashes in user response models.
- **Session ownership**: Validate that `session.user_id == current_user.id` on all session-related endpoints.
